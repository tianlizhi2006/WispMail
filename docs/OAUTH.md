# OAuth2 浏览器授权登录

WispMail 用 OAuth2 登录微软账户：Outlook.com / Hotmail / Live，以及 Microsoft 365 工作或学校账户。

不计划接入 Gmail 的 OAuth 登录：Google 把读写邮件列为受限权限，未通过付费安全审核的应用最多只能给 100 个用户使用，登录时会显示“未验证的应用”警告；在测试状态下授权还会每 7 天失效。Gmail 用户可以开启两步验证后使用应用专用密码，按“常见邮箱”方式添加。

## 工作方式

1. 用户点击「在浏览器中登录微软账户」。WispMail 在本机回环地址开一个临时端口，并用系统浏览器打开微软登录页。流程为授权码 + PKCE，不使用客户端密钥。
2. 用户登录并同意授权后，浏览器跳转回 `http://localhost:<端口>`。WispMail 校验 `state`，再用授权码换取令牌。
3. 从 `id_token` 读取邮箱地址和账户类型：
   - 个人账户使用 `smtp-mail.outlook.com`；
   - 工作或学校账户使用 `smtp.office365.com`；
   - 收信统一使用 `outlook.office365.com`。
4. 令牌换取后，用访问令牌通过 XOAUTH2 验证 IMAP 和 SMTP。两端都成功后才保存账户。
5. 令牌的保存与使用：
   - 刷新令牌保存在系统凭据管理器中。Windows 单条凭据有长度上限，超长令牌会自动分段保存。
   - 访问令牌只缓存在内存中，到期前 5 分钟自动刷新。
   - 微软轮换刷新令牌后，新令牌会立即写回凭据管理器。
6. 令牌只会发给上面列出的微软服务器。账户配置被改成其他主机时，连接前就会被拒绝。

授权失效时（例如修改了密码或撤销了授权），同步会提示重新登录。在「编辑账户」中点击「重新登录微软账户」即可，登录的必须是同一个邮箱。

## 为发行版注册应用 ID（开发者）

每个发行版需要在微软 Entra 注册一个应用，并把它的「应用程序(客户端) ID」编译进程序。

1. 打开 <https://entra.microsoft.com>，或 Azure 门户中的「Microsoft Entra ID」，进入「应用注册」，点「新注册」。
   - 名称：`WispMail`。
   - 受支持的帐户类型：**任何组织目录中的帐户和个人 Microsoft 帐户**。
   - 重定向 URI：平台选 **公共客户端/本机(移动和桌面)**，值填 `http://localhost`。端口无需填写，微软会忽略回环地址的端口。
2. 注册完成后，在「概述」页复制 **应用程序(客户端) ID**。
3. 「API 权限」可以不预先添加，首次登录时用户会看到所需权限并同意。如果希望在后台列出，可添加 Microsoft Graph 的委托权限：
   - `IMAP.AccessAsUser.All`
   - `SMTP.Send`
   - `offline_access`
   - `openid`
   - `email`
   - `profile`
4. 不需要创建客户端密码或证书。

构建时通过环境变量内置 ID：

```powershell
$env:WISPMAIL_MICROSOFT_CLIENT_ID = "00000000-0000-0000-0000-000000000000"
npm run tauri build
```

开发时也可以只在运行前设置同名环境变量（`npm run tauri dev`），程序会优先使用运行时的值。未设置 ID 的构建中，「Outlook / 微软」方式会提示无法登录，其他登录方式不受影响。

应用 ID 不是机密，可以随程序分发。本机回调和 PKCE 保证只有发起登录的这次 WispMail 能换取令牌。

## 常见问题

- **工作或学校账户提示需要管理员批准**：组织禁止用户自行同意第三方应用，需要 IT 管理员在 Entra 中为 WispMail 授予同意。
- **IMAP 拒绝了账户授权**：
  - Microsoft 365 管理员可能为该邮箱关闭了 IMAP 或 SMTP AUTH，需要在 Exchange 管理中心开启。
  - 个人账户可在 Outlook.com 的「设置 → 邮件 → 转发和 IMAP」中确认 IMAP 已开启。
- **浏览器没有自动打开**：检查系统默认浏览器设置。登录页面打开后，可在 5 分钟内完成，超时需重新开始。
