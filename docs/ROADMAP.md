# WispMail 开发路线图

README 说明"要做什么"，本文档说明"按什么顺序做、每一步做到什么程度算完成"。
每个里程碑都应当是一个**可运行、可演示**的版本，而不是一堆半成品模块。

---

## 原则

1. **纵向切片**：每个里程碑打通"界面 → 后端 → 服务器"的完整链路，再横向扩展。
2. **先 IMAP，后 POP3**：IMAP 覆盖绝大多数邮箱且支持多端同步，POP3 作为补充。
3. **先密码 / 授权码，后 OAuth2**：国内邮箱和自建邮箱都用授权码，可以最快验证收发链路；OAuth2 需要先在 Google / 微软注册应用，放在后面。
4. **安全不推迟**：HTML 过滤、远程图片拦截、凭据存放在系统凭据管理器，从第一次显示邮件起就到位，不留"以后再补"。
5. **轻量有指标**：每个里程碑结束时记录安装包大小、冷启动时间和空闲内存，防止体积悄悄膨胀。

## 里程碑

### M0 · 项目骨架 ✅

- [x] Tauri 2 + SolidJS 工程，前后端可编译
- [x] 后端按 account / sync / storage 分层，前端三栏布局外壳
- [x] 常见邮箱服务商的配置自动识别（内置表 + 命名规则兜底）
- [x] CI：类型检查、格式检查、Clippy、单元测试

### M1 · 添加账户

目标：用户可以添加一个邮箱，客户端验证能连上。

- [ ] "添加账户"界面：输入邮箱 → 自动填充服务器配置 → 可手动修改
- [ ] 显示服务商提示（如"需要授权码"）
- [ ] 测试连接：分别验证 IMAP 登录与 SMTP 登录，给出明确的错误原因
- [ ] 凭据写入系统凭据管理器；账户配置写入本地数据库
- [ ] 账户列表：查看、编辑、删除

**完成标准**：用 QQ 邮箱和一个自建邮箱分别成功添加账户，重启后账户仍在。

### M2 · 收信与阅读

目标：能看到邮件。

- [ ] 拉取文件夹列表，左栏显示
- [ ] 同步收件箱最近的邮件头，中栏显示列表
- [ ] 点开邮件后下载并解析正文，右栏显示
- [ ] HTML 邮件在隔离环境中显示，过滤脚本，默认拦截远程图片
- [ ] 本地缓存：已同步的邮件离线可读
- [ ] 增量同步，不每次全量拉取

**完成标准**：一个上千封邮件的收件箱，首次同步可用，再次打开秒开。

### M3 · 写信与发送

目标：能发邮件。

- [ ] 撰写窗口：收件人、抄送、密送、主题、正文
- [ ] 回复、全部回复、转发（正确引用原文与邮件头）
- [ ] 添加附件
- [ ] 发送后存入"已发送"文件夹
- [ ] 草稿自动保存

**完成标准**：在各内置服务商之间互发带附件的邮件，对方显示正常。

### M4 · 日常整理

目标：可以替代网页版完成日常操作。

- [ ] 已读 / 未读、星标、删除、移动、归档，同步回服务器
- [ ] 多选与批量操作
- [ ] 新邮件实时到达（IMAP IDLE）与系统通知
- [ ] 本地全文搜索
- [ ] 托盘常驻、键盘快捷键

**完成标准**：作者本人用 WispMail 连续一周处理日常邮件。

### M5 · 第一个公开版本 (v0.1)

- [ ] Gmail / Outlook 的 OAuth2 登录
- [ ] 统一收件箱
- [ ] 多账户签名
- [ ] POP3 收信
- [ ] Windows 安装包与自动更新
- [ ] 发布说明与使用文档

之后进入 README 中的"第二阶段：增强体验"。

## 轻量指标（目标值）

| 指标 | 目标 |
|---|---|
| 安装包大小 | < 15 MB |
| 冷启动到可交互 | < 1 秒 |
| 空闲内存占用 | < 150 MB |

每个里程碑结束时在此表下方记录实测值。
