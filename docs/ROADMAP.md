# WispMail 开发路线图

README 说明"要做什么"，本文档说明"按什么顺序做、每一步做到什么程度算完成"。
每个里程碑都应当是一个**可运行、可演示**的版本，而不是一堆半成品模块。

---

## 原则

1. **纵向切片**：每个里程碑打通"界面 → 后端 → 服务器"的完整链路，再横向扩展。
2. **先 IMAP，后 POP3**：IMAP 覆盖绝大多数邮箱且支持多端同步，POP3 作为补充。
3. **先密码 / 授权码，后 OAuth2**：国内邮箱和自建邮箱都用授权码，可以最快验证收发链路；OAuth2 需要先在 Google / 微软注册应用，放在后面。
4. **安全不推迟**：HTML 活动内容过滤、远程图片加载控制、凭据存放在系统凭据管理器，从第一次显示邮件起就到位，不留"以后再补"。
5. **轻量有指标**：每个里程碑结束时记录安装包大小、冷启动时间和空闲内存，防止体积悄悄膨胀。

## 里程碑

### M0 · 项目骨架 ✅

- [x] Tauri 2 + SolidJS 工程，前后端可编译
- [x] 后端按 account / sync / storage 分层，前端三栏布局外壳
- [x] 常见邮箱服务商的配置自动识别（内置表 + 命名规则兜底）
- [x] CI：类型检查、格式检查、Clippy、单元测试

### M1 · 添加账户

目标：用户可以添加一个邮箱，客户端验证能连上。

- [x] "添加账户"界面：输入邮箱 → 自动填充服务器配置 → 可手动修改
- [x] 显示服务商提示（如"需要授权码"）
- [x] 测试连接：分别验证 IMAP 登录与 SMTP 登录，给出明确的错误原因
- [x] 凭据写入系统凭据管理器；账户配置写入本地数据库
- [x] 账户列表：查看、编辑、删除
- [x] 自建 / 域名邮箱手动配置，独立收发信用户名和可选独立 SMTP 密码，兼容旧账户

**完成标准**：用 QQ 邮箱和一个自建邮箱分别成功添加账户，重启后账户仍在。

实现已落地，真实 QQ / 自建邮箱验收及剩余轻量指标测量待完成，因此暂不将 M1 标记为完成。当前支持自定义收发信登录用户名、共用或独立密码 / 授权码、IMAP 及 TLS / STARTTLS。验证步骤见 [开发与验证指南](DEVELOPMENT.md) 和 [自建邮箱接入](SELF_HOSTED.md)。

### M2 · 收信与阅读

目标：能看到邮件。

- [x] 拉取文件夹列表，左栏显示
- [x] 同步收件箱最近的邮件头，中栏显示列表（每页 50 封）
- [x] 点开邮件后下载并解析正文，右栏显示
- [x] HTML 邮件在隔离环境中保留原有图文排版，过滤邮件脚本，支持 CID / Content-Location 与网络图片
- [x] 按邮件控制网络图片显示，安全打开正文网页链接
- [x] 本地缓存：已下载的正文及附件离线可读
- [ ] 增量同步，不每次全量拉取

**完成标准**：一个上千封邮件的收件箱，首次同步可用，再次打开秒开。

目前按 UID 分页同步摘要并保留已下载正文，处理 UIDVALIDITY 变化和服务器端删除；严格增量同步与真实大邮箱性能验收尚未完成。

### M3 · 写信与发送

目标：能发邮件。

- [x] 撰写窗口：收件人、抄送、密送、主题、正文
- [x] 回复、全部回复（引用原文与邮件头）
- [x] 转发（保留原邮件 HTML 排版与 CID 内嵌图片；超出发送限制的附件会提示）
- [x] 添加附件
- [x] 发送后存入"已发送"文件夹（归档失败单独提示，不重复发送）
- [x] 草稿自动保存（每账户一份本地草稿，含附件）

**完成标准**：在各内置服务商之间互发带附件的邮件，对方显示正常。

收发链路已使用本地 TLS IMAP / SMTP 服务器验证，真实自建服务器与各服务商互发验收仍需完成。

### M4 · 日常整理

目标：可以替代网页版完成日常操作。

- [x] 已读 / 未读同步回服务器
- [x] 星标、删除、移动、归档，同步回服务器
- [x] 多选与批量操作（已读 / 未读、星标、归档、删除、移动）
- [x] 新邮件实时到达（IMAP IDLE，不支持时轮询 STATUS）与系统通知
- [x] 本地全文搜索（SQLite FTS5 trigram，覆盖已同步的邮件头和已下载的正文）
- [x] 托盘常驻、开机自启
- [ ] 键盘快捷键（已支持 Ctrl+F 搜索）

**完成标准**：作者本人用 WispMail 连续一周处理日常邮件。

### M5 · 第一个公开版本 (v0.1)

- [x] Outlook / Microsoft 365 的 OAuth2 登录（授权码 + PKCE，XOAUTH2，见 [OAuth 说明](OAUTH.md)）
  - Gmail 授权登录已取消：受限权限需要付费安全审核；Gmail 使用应用专用密码登录。
- [ ] 统一收件箱
- [ ] 多账户签名
- [ ] POP3 收信
- [ ] Windows 安装包与自动更新
- [ ] 发布说明与使用文档

之后进入 README 中的"第二阶段：增强体验"。

## 轻量指标（目标值）

| 指标 | 目标 |
|---|---|
| 安装包大小 | < 15 MB |
| 冷启动到可交互 | < 1 秒 |
| 空闲内存占用 | < 150 MB |

每个里程碑结束时在此表下方记录实测值。

### 2026-11-02 · M1 轻量化简查

Windows x64 release 构建，未添加账户；本次仅移除未使用的 opener 插件。

| 项目 | 结果 |
|---|---|
| 前端 JS + CSS | 48.35 KB（未 gzip） |
| release 主程序 | 6.37 MB（不是安装包大小） |
| 空闲内存采样 | 启动 10 秒后，主程序及 6 个 WebView2 子进程的私有工作集合计 88.24 MB |
| 其他内存口径 | 工作集合计 374.83 MB（共享页会重复计入）；私有提交内存 344.39 MB，均不等于私有驻留内存 |
| 安装包 < 15 MB | 未验证：NSIS 工具下载超时，程序编译成功但未生成安装包 |
| 冷启动到可交互 < 1 秒 | 未测量 |

以上 MB / KB 使用十进制单位。当前没有后台轮询，网络验证仅由用户操作触发；依赖按需启用功能。私有工作集采样低于 150 MB，但路线图尚未统一内存统计口径，也未完成安装包和冷启动测量，因此不能认定全部指标达标。

### 2026-11-02 · 核心收发构建

已通过 `npm run tauri build -- --no-bundle` 生成 Windows x64 主程序：7,570,432 字节（7.57 MB）。生产前端 JS + CSS 合计约 123.7 KB，gzip 合计约 41.3 KB；浏览器测试夹具未包含在生产构建中。新增依赖用于 MIME / 中文编码、HTML 过滤和原生附件保存；继续按需连接，无后台定时轮询。此阶段未重新测量内存和冷启动，也未生成安装包，不能沿用前一阶段的内存数据作为本阶段验收值。

### 2026-11-02 · 完整图文阅读构建

更新后的 Windows x64 release 主程序为 7,737,856 字节（7.74 MB），前端 JS / CSS gzip 合计约 46.1 KB。正文恢复原有 HTML / CSS 与内嵌图片、网络图片、受控链接；同一内嵌图片重复引用时不重复展开编码数据。浏览器回归依赖仅用于开发，不包含浏览器或测试夹具到正式程序。本次未重测内存、冷启动或安装包。
