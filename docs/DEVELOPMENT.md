# 开发与验证

## 运行

需要 Node.js LTS、Rust stable，以及 Windows Visual Studio C++ 生成工具。

```sh
npm ci
npm run tauri dev
```

`npm run dev` 只启动前端预览，不提供桌面 IPC 和系统凭据存储。请使用 Tauri 窗口验证账户操作。

## 账户管理

- 输入邮箱地址后识别服务商；未知域名给出 `imap.域名` / `smtp.域名` 建议，必须核对。
- 自建 / 域名邮箱可选择手动配置，邮箱地址变化不会覆盖手工填写的服务器信息。
- IMAP 和 SMTP 可分别设置登录用户名，留空默认使用邮箱地址；支持管理员分配的普通用户名或 `DOMAIN\user` 等格式。
- 默认收发信共用密码 / 授权码；关闭“发信使用收信密码”可设置独立 SMTP 密码。旧账户自动沿用原邮箱用户名和共用密码。
- 当前支持 IMAP、SMTP、TLS 和强制 STARTTLS。证书必须受系统信任且与服务器主机名匹配，不提供跳过证书验证的选项。
- QQ、网易等服务商需要先在网页版开启 IMAP / SMTP，并生成授权码。应用内密码栏填写授权码。
- OAuth2 尚未实现。Gmail 等服务商是否允许应用专用密码由服务商及账户策略决定；不支持密码登录的账户需要等待 OAuth2。
- “测试连接”分别验证两端登录，不发信、不下载邮件、不保存账户。保存时重新验证当前表单，两端成功后才写入账户和凭据。
- 编辑账户时密码留空沿用系统凭据管理器中的凭据；输入新密码会在验证成功后更新凭据。首次从共用密码切换到独立 SMTP 密码时必须填写发信密码；切回共用密码时移除不再使用的 SMTP 凭据。
- 删除账户会移除本机账户配置、凭据、邮件缓存与未发送的本地草稿，不删除服务器中的邮件或邮箱。

账户配置保存在 Tauri 应用数据目录的 `wispmail.sqlite3` 中，Windows 通常位于 `%APPDATA%\com.wispmail.app\`。密码 / 授权码只存入系统凭据管理器，不出现在账户列表返回值、SQLite 表或浏览器持久化存储中。数据库与凭据系统不是同一个事务资源，操作失败时会尝试回滚；若系统凭据管理器持续拒绝访问，界面会显示失败信息。

邮件功能将数据库事务性升级到 schema 2，保留原账户并增加文件夹、邮件和本地草稿表。网络等待不持有缓存数据库锁；同一账户网络操作按序执行，不同账户最多并行四个。账户邮箱身份或收信端配置改变时清理旧邮件缓存，保留本地草稿。

## 自动检查

```sh
npm run typecheck
npm test
npm run test:render
npm run build
cd src-tauri
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

自动测试使用本机测试数据及模拟凭据存储，不读取用户已有账户或邮箱密码，不访问真实邮箱。Windows 是当前 CI 和首发平台；macOS / Linux 仍需要独立平台验收。

核心收发的浏览器验证覆盖草稿恢复、显式发送、回复线程头、模拟发送后清草稿、离线阅读、UIDVALIDITY 分页重置和空收件箱清理旧阅读内容。自动化文件选择器超时，因此附件选择 / 原生保存对话框仍需桌面实测；附件解析、草稿持久化和 SMTP 附件投递已由自动测试覆盖。

2026-11-02 完整图文阅读更新：101 项 Rust 测试、29 项 Node 测试及 4 个真实 Edge 浏览器场景通过。类型检查、Clippy、前端构建和 Windows release 主程序构建通过。验证包括原始 head / inline CSS、表格 / 背景 / 媒体查询、CID / Content-Location / data 图片、HTTP / HTTPS 图片默认加载及关闭后的零网络请求，以及实际阅读器的附件去重、显式图片附件保留下载条目、链接转交、已读更新不重载正文。邮件脚本、事件、表单、嵌套页面和 meta 刷新仍被阻止。

## 浏览器 UI 夹具

启动 `npm run dev` 后打开 `http://localhost:1420/tests/mail-ui.html`。该页明确标注本地模拟测试，使用真实前端组件和内存中的虚构账户，可模拟离线、邮箱重建、服务器清空收件箱、延迟响应、草稿和发送。底部可展开查看调用次数和模拟发送内容。夹具不会连接真实邮箱、读取系统凭据或发送真实邮件，也不包含在生产入口构建中。

`npm run test:render` 使用仅开发依赖的 `playwright-core` 和电脑已安装的 Edge / Chrome，自动启动临时本地 Vite / HTTPS 测试服务，不下载浏览器、不使用现有用户浏览器配置。可用 `PLAYWRIGHT_EXECUTABLE_PATH` 指定浏览器路径。网络图片只请求本地测试服务，测试证书仅在隔离测试上下文中放行；生产 TLS 验证不受影响。截图和报告输出到已忽略的 `artifacts/mail-render/`。

生成可直接运行的 Windows 主程序可用 `npm run tauri build -- --no-bundle`，输出 `src-tauri/target/release/wispmail.exe`。这不会生成安装包；依赖系统已安装的 WebView2。

## 真实邮箱验收

下面的流程需要由持有邮箱授权码的测试者完成。单元测试或编译成功不等于已完成真实服务商验收。

1. 添加 QQ 邮箱，检查自动配置与授权码提示，测试 IMAP / SMTP 并保存。
2. 按 [自建邮箱指南](SELF_HOSTED.md) 添加一个自建域名邮箱，使用管理员提供的主机、端口和登录用户名，验证 TLS 或 STARTTLS 登录并保存。若 SMTP 凭据不同，关闭共用密码并填写独立密码。
3. 关闭并重启应用，确认两个账户仍在；编辑显示名并将密码留空，确认能再次验证和保存。
4. 输入错误授权码或错误主机地址，确认界面分别展示连接失败原因，失败保存不会覆盖原账户。
5. 在两次连接测试之间修改配置，确认旧结果清除，保存使用最新配置重测。
6. 同步多页邮件，打开中文、HTML-only 和带附件的邮件，检查附件保存的文件内容一致；断网后确认已下载正文仍可阅读。
7. 给自己的另一测试邮箱发送纯文本和附件，验证收件人、抄送、密送、回复链及服务器已发送副本；测试只针对你明确指定的测试邮箱。
8. 保存含附件的本地草稿并重启应用，恢复后发送，确认草稿被清理；发送连接中断时先核对服务器记录，避免重复发送。
9. 删除专用测试账户，重启后确认本机账户、缓存和草稿中已移除，服务器邮箱保持可用。

真实邮箱验收尚待完成；已做的轻量化采样及未完成指标见 [路线图](ROADMAP.md)，不将本地协议测试等同于真实服务器验收。
