# 自建 / 域名邮箱接入

WispMail 连接已经部署的 IMAP 和 SMTP 邮件服务器，支持账户配置、文件夹浏览、邮件同步与阅读、新建 / 回复 / 全部回复、附件收发和本地草稿。

## 准备信息

向服务器管理员确认邮箱地址、收发信主机、端口、加密方式和登录凭据。收发信主机可以相同，登录用户名也可以与邮箱地址不同。例如：

| 设置 | 示例 |
|---|---|
| 邮箱地址 | `alice@team.example` |
| 收信服务器 | `mail.team.example`，端口 `993`，SSL / TLS |
| 收信用户名 | `alice` |
| 发信服务器 | `mail.team.example`，端口 `587`，STARTTLS |
| 发信用户名 | `TEAM\alice`，也可与收信用户名相同 |
| 发信密码 | 默认使用收信密码；如不同，可单独填写 |

上述地址仅为示例，请替换为实际服务器信息。不要把 `https://`、路径或端口一起填进“服务器地址”。不需要域名符合 `imap.域名` / `smtp.域名` 的命名规则。

## 在应用中添加

1. 添加邮箱，选择“自建 / 域名邮箱”手动配置方式。
2. 填写邮箱地址、收发信服务器、端口及加密方式。
3. 分别填写登录用户名；留空时使用邮箱地址。填写收信密码。
4. 如果两端密码不同，关闭“发信使用收信密码”，填写发信密码；这个开关不影响独立的发信用户名。
5. 点击“测试连接”，检查 IMAP 与 SMTP 两项结果。此操作不会发送或下载邮件，也不会保存账户。
6. 点击“验证并保存”。两端都通过验证后，配置写入本机数据库，密码写入系统凭据管理器。

手动模式下，修改邮箱地址不会触发自动配置或改写服务器。已有账户默认按手动配置编辑；用户名、服务器和密码模式会在重启后保留。编辑时留空密码表示保留对应的已保存凭据。首次启用独立 SMTP 密码时必须填写；切回共用密码会移除旧的独立 SMTP 凭据。

## 收信、阅读与发送

- 添加账户后进入邮箱，先显示本地缓存，再同步服务器文件夹和最近 50 封邮件摘要；点击“加载更早的邮件”继续翻页。需要新邮件时点击刷新，当前没有后台定时轮询或实时推送。
- 点击邮件后下载正文并缓存。已下载邮件可离线阅读，附件也可离线另存为；尚未下载的正文需要连接服务器。
- HTML 保留原有表格、字体、颜色、内嵌 CSS、背景和图文排版。邮件的 CID / Content-Location 图片会在正文对应位置显示，已用于正文的图片不再重复列为普通附件；普通附件仍可保存。
- 默认显示 HTTP / HTTPS 网络图片，可通过“隐藏网络图片”切换，正文内嵌图片仍可显示。网络图片需要网络连接；邮件自带图片随原始邮件缓存，离线仍可阅读。
- 邮件脚本、事件处理器、表单和嵌套页面仍被移除。正文运行于隔离框架，只有应用自身用于高度调整和链接点击的受控脚本可运行；邮件不能访问主程序或本机文件。可切换纯文本视图。
- 点击正文中的 HTTP / HTTPS 链接会交给系统浏览器，`mailto:` 交给系统默认邮件应用；不允许 `file:`、`javascript:` 等链接。外部样式表和脚本不会加载。
- 打开邮件会尝试同步已读状态；连接失败时保留正文阅读并提示已读未同步。工具栏可显式标记已读 / 未读。
- “写邮件 / 继续草稿”打开当前账户的本地草稿；支持抄送、密送和文件附件。回复使用 Reply-To / From，并保留有效的 In-Reply-To / References。
- 草稿自动保存到本机数据库，每账户一份，包含附件。关闭写信窗口会等待保存完成；已有草稿时回复另一封邮件，会先让你选择继续原草稿或舍弃后回复。本地草稿不上传到服务器 Drafts 文件夹。
- “发送”是唯一发信入口。SMTP 接受后，客户端向服务器的已发送文件夹保存副本；找不到该文件夹时尝试创建 `Sent`。副本保存失败会明确提示“已发送，但未能保存副本”，不要因此重复发送。
- 如果发送时连接中断或超时，结果可能不确定；草稿会保留。请先检查服务器记录或向收件人确认，再决定重试。客户端不会自动重投邮件。

## 当前边界

每个文件夹最多处理 100000 封邮件索引，摘要每页 50 封；单封原始邮件最多下载 20 MiB，已接受邮件的 HTML 和纯文本正文完整显示，不再按 1 MiB 截断。发送正文上限为 1 MiB，最多 50 个收件人、20 个附件，附件合计不超过 10 MiB；保存收到的单个附件也限制为 10 MiB。超限会显示提示，不会静默发送或保存截断的附件。

邮件删除 / 移动、文件夹管理、转发、全文搜索和 IMAP IDLE 尚未实现。服务器若自行保存发信副本，可能与客户端 APPEND 产生重复副本，验收时请确认服务器策略。

## 连接要求与排查

- 支持密码认证的 IMAP / SMTP，要求 TLS 或强制 STARTTLS。常见端口为 IMAP `993/TLS`、`143/STARTTLS`，SMTP `465/TLS`、`587/STARTTLS`；管理员提供的自定义端口也可使用。
- 服务器证书必须受系统信任，并匹配填写的服务器地址。使用内网 CA 时，应由管理员通过正常的系统证书管理流程部署信任；应用不会忽略证书错误。
- 连接失败先核对主机、端口和防火墙；TLS 失败核对加密方式、证书域名和有效期；认证失败核对各端用户名及对应密码。
- 当前要求 SMTP 登录认证，尚不支持免认证中继、客户端证书登录、POP3 或 OAuth2。
- 自动识别未知域名时给出的主机是命名猜测，并非 DNS / MX 或服务器探测结果。

真实服务器验收时，请覆盖两端共用密码、独立凭据、文件夹翻页、中文正文、附件完整性、回复链、密送、已发送归档、草稿重启恢复，以及断网后阅读已下载邮件。自动测试使用本地 TLS 服务器和模拟凭据存储，不替代实际部署环境的验证。
